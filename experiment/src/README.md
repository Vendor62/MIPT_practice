# `src/` — основная логика эксперимента

Здесь лежит публичная версия кода, который реализует протокол оценки гибридного
отслеживания сюжетов. Это «справочная» реализация: она показывает, как считались
метрики и как выглядело решение по объединению постов в истории, но не содержит
приватных источников данных.

## Ключевые файлы

- `build_dataset.py` — сборка размеченного набора (manual gold). Здесь же лежит
  проверка изоляции названий историй между двумя источниками разметки, чтобы
  одинаковые «сырые» идентификаторы случайно не склеились в одну историю.
- `build_pairwise_features.py` — расчёт признаков для пар постов: смысловая
  близость, временная близость, пересечение сущностей. Графовые признаки
  оставлены как интерфейс-заглушка.
- `metrics.py` — реализация метрик качества кластеризации: pairwise precision/recall/F1,
  ARI, NMI, доля ложных склеек (false merge rate) и доля ложных разделений
  (false split rate).
- `evaluate_online_assignment.py` — оценка решения в режиме «онлайн»: посты
  приходят в хронологическом порядке, для каждого выбирается либо «приклеить
  к существующей истории», либо «начать новую». Здесь же — подбор порога
  на dev-подвыборке с ограничениями против лишних склеек.
- `evaluate_llm_baseline.py` — внешний LLM в роли судьи (DeepSeek Chat,
  совместимый с OpenAI API). Размеченные метки **никогда** не подаются в
  промпт — модель видит только текст поста и список историй-кандидатов.
- `plotting.py` — построение итоговых графиков из таблиц в `results/`. Картинки
  локальные, в репозиторий не коммитятся.
- `utils.py` — общие вспомогательные функции: чтение и запись CSV/JSON,
  разбор времени, устойчивая сортировка постов по времени.

## Что важно знать

- Размеченные метки используются **только** для расчёта метрик и подбора порога
  на dev-подвыборке. В само решение по объединению постов они не попадают.
- В LLM-промпт размеченные метки тоже не попадают — это сохраняет честность
  сравнения.
